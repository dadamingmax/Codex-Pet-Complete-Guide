上周，Codex悄悄更新了。

大多数人注意到的，是屏幕角落突然多了一只会动的宠物。

**宠物是表面。真正藏在里面的，是一套让Agent持续干活的新机制。**

今天这篇，帮你把这次Codex更新吃透——`/pet`怎么玩，宠物怎么自制，`/goal`到底解决了什么问题。



# 一、说一下那只宠物：它不是摆设

输入 `/pet`，Codex桌面端的角落会冒出一只小动物。


![](https://files.mdnice.com/user/166515/ad4b4d60-94c2-47a9-b299-a19e45a814b7.png)

可以悬浮、跨App显示。会随着任务状态变换动作。

这就**解决**了一个真实的**痛点**：**让你知道Codex在跑、有没有卡住、是不是在等我输入？**

首先确认你用的是 **Codex桌面端App**，不是纯CLI。

# 三、进阶：用 /hatch 搞一只自己的宠物

不喜欢内置的可以自己造一只。

Codex 支持通过 `hatch-pet` skill创建自定义宠物。

**第一步：安装skill**：直接输入`$skill-installer hatch-pet`

**第二步：重载skill**：按`Cmd/Ctrl + K`跑`Force Reload Skills`

**第三步：给出提示词，让它帮你生成，或者通过 image2 生成参考图，让其参考图片生成宠物**

直接抄这个模板，改一改就行：
```
帮我创建一只 Codex 电子宠物。
宠物名称：yinienie
宠物类型：像素风小黑猫
视觉风格：极简，轮廓清晰，适合桌面悬浮
性格设定：傲娇但靠谱，发现问题会直接提醒
主要颜色：黑色 + 绿色眼睛
标志元素：脖子上挂一块小代码牌
动作状态：
1. idle 待机
2. working 敲代码中
3. thinking 歪头冒问号
4. waiting 等待输入
5. done 开心跳一下
6. sleeping 趴下睡觉
要求：无背景、无文字、缩小后轮廓依然清晰
```

提示词越具体，生成结果越稳。
记住：
1. 轮廓要清楚（缩到角落还认得出来吗）；
2. 颜色控制在2-4个；
3. 动作要有状态感，待机/工作/完成各不同；
4. 人设要具体，别只写"可爱"，写"傲娇但认真"生成结果稳多了。

还有就是：不加文字。 宠物那么小，字上去必糊。

# 四、重头戏：/goal

以前Agent跑一轮就停，你得手动推下一步。

**/goal** 之后：告诉它目标，它自己持续开，你只管关键节点审查。

从手动挡，变成自动导航。

# 五、/goal 怎么开启？

**手动打开**。

编辑配置文件：
`
~/.codex/config.toml
`

加入：
`
[features]
goals = true
`

或者直接命令行：
`
codex update
codex features enable goals
`

开启之后，核心命令就这几个：

| 命令 | 作用 |
|------|------|
| `/goal <目标描述>` | 创建目标，开始持续执行 |
| `/goal pause` | 暂停，中途检查用 |
| `/goal unpause` | 继续执行 |
| `/goal clear` | 清除目标，重新来 |

**pause/unpause这对命令非常重要。**

Agent跑偏了不要直接Ctrl+C粗暴停，先pause，看看跑到哪了，补充上下文，再unpause继续。

# 六、goal 怎么才好用？

一个好用的goal要包含4个要素：
**任务目标、执行边界、验收标准、输出要求。**

**修bug：**
```
/goal 修复登录页点击后偶发loading卡死问题。
先定位原因，再做最小改动。
验收：登录正常结束，失败时能恢复按钮状态。
最后总结改动文件和潜在风险。
```

**重构：**
```
/goal 把Dashboard页面重复卡片结构拆成可复用组件。
不改接口逻辑，不改视觉效果。
完成后跑类型检查，总结拆分思路。
```

**补测试：**
```
/goal 为订单状态转换逻辑补测试。
先读现有测试风格，再覆盖正常流、异常流、边界情况。
跑完说明覆盖了哪些场景。
```

记住：**目标越清晰，它跑偏的概率越低。**


# 七、什么时候用，什么时候不用？

**适合 `/goal` 的场景：**

- 项目重构（改动多、轮次长）
- 批量修bug（重复劳动，交给它跑）
- 补测试、写文档（不需要每步确认）
- 排查复杂问题（让它先探路）

**人工介入的场景：**

- 涉及支付、权限、数据删除
- 改动核心业务逻辑
- 生产环境部署前

**让Codex执行重复劳动，让自己做最后的判断。**
